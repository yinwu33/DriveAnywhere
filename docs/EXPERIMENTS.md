# 实验登记表

## 约定

- **启动前**：在"条目"里写方案，包括假设、相对基线改了什么、命令或配置、代码 commit、输出目录、预期、判定标准，然后提交。
- **结束后**：补结果，包括关键数字、图的路径、结论、下一步，更新总表状态，然后提交。失败或中止的实验也要记。
- 编号：正式实验用 `E<n>`（`E5f` 这类后缀表示同一实验的变体）；只读诊断用 `D-<字母><n>`；oracle 上界用 `U<n>`。
- 默认场景：val056（只在一个场景上迭代，扩到 5 个场景要用户同意）。
- 指标口径：
  - "FRONT 留出"是 `scripts/eval_front_heldout.py` 的 19 个留出帧，整图 PSNR / LPIPS。
  - "侧视未观测"是 `scripts/eval_cross_camera.py --cams 1 2 3 4 --region_ref results/E5c/val056`，只在 E5c 定义的同一组未观测像素上算 PSNR / LPIPS。只有 SIDE_LEFT / SIDE_RIGHT 可以和 U3 比。
  - "验收通过率"是空洞像素中通过 `validate_generated_views.py` 的比例。它只说明生成的 RGB-D 自洽，不说明隐藏内容正确。

## 条目

### D-A1 / D-A2：侧视垃圾的来源

- **方案**（DECISIONS W）：
  - 逐个高斯统计：FRONT 训练视角中受约束像素上的混合权重（support）、尺寸、离 NKSR 网格的距离、needle 比例、DC 饱和度。
  - 在内存里改参数，同一个 checkpoint 渲染固定相机（frame 96 / 104 / 112 × 偏航 −90 / −60 / 0 / 60 / 90 / 180）和 FRONT 留出帧。
  - 脚本：`scripts/diagnose_floaters.py`，commit `efc29cf`（A1）/ `b864c7b`（A2）。
  - 输出：`results/_diagnostics/floaters/val056/E5c_a`、`E5c_b`。
- **结果**：见 DECISIONS W1。
  - 去掉 support < 1 的 18.8 万个高斯只去掉 1.9% 的侧视权重；只用 DC 颜色也去不掉彩色块。
  - 侧视权重集中在大尺寸、离网格远的高斯上（1.2% 的高斯贡献 80%），FRONT 离不开它们：最大轴 > 1 剪掉后 FRONT 留出 29.45，离网格 > 1 剪掉后 20.55。剪掉后侧视露出来的几乎全是空的。
- **结论**：侧面基本没被重建出来。FRONT 用一层只在前向成立的大高斯拟合远处和边缘；现有空洞判断不把这些像素算作空洞。

### D-B1：生成帧的联合深度

- **方案**：同一组生成帧、同一套验收参数，只换深度来源（MoGe / MapAnything × 全局 / 逐空洞尺度）。脚本 `scripts/run_depth_probe.py`，commit `efc29cf`、`7bcd38a`、`042554d`；输出 `results/_diagnostics/depth_probe/val056/{E13_r0,E13_r0_ma,E12_drive}`。
- **结果**：MapAnything 联合深度（全局尺度）让 E13 第 1 轮的验收通过率从 0.11% 升到 3.57%，E12 drive 从 8.73% 升到 20.23%。MapAnything 基本遵守给定位姿（相对第 0 帧旋转误差中位数 0.5–0.6°）。仍有 53–64% 的空洞像素没有证据；E13 原地转动时，67–112° 的侧视只有 0.2% 通过。
- **结论**：生成帧深度改用 MapAnything 联合推理；侧视轨迹要带平移。

### D-A3：按观测视角锥屏蔽高斯

- **假设**：D-A2 的垃圾高斯只在 FRONT 的观测方向上成立。如果渲染新视角时，把视线偏离其观测方向太多的高斯淡出，侧视会露出真正的空洞（可以交给生成），而 FRONT 不受影响。
- **方法**（`dashrecon/gen/floaters.py` `observation_cone` / `cone_gate`，`scripts/diagnose_floaters.py` 的 `gate<余量>` 变体，commit `fb0fd6c`）：
  - 每个高斯的观测锥：所有训练视角混合权重加权的平均观测方向（轴），以及在该视角权重 ≥ 0.5 像素的视角中与轴的最大夹角（半角）。没有这种视角的高斯记为"未观测"。
  - 新视角下的偏离角 = max(0, 视线与轴的夹角 − 半角)。不透明度乘以 clamp(1 − (偏离角 − 余量) / 15°, 0, 1)；未观测的高斯乘以 0。
  - 固定相机：frame 96 / 104 / 112 × 偏航 −90 / −60 / −30 / 0 / 30 / 60 / 90 / 180。
  - 输出：`results/_diagnostics/floaters/val056/E5c_gate`。
  - 为腾出显存，运行期间临时停了 8080 查看器，跑完已按原参数恢复。
- **结果**：
  - 观测锥：59% 的高斯至少在一个视角有 ≥ 0.5 像素的权重；已观测高斯的半角中位数 7.6°（p10 2.9°，p90 13.1°）。
  - 曝光比例指原本不透明、屏蔽后变透明的侧视像素占比，按偏航平均：

    | 变体 | 屏蔽对象 | FRONT 留出 PSNR / LPIPS | −90° | −60° | −30° | 0° | 30° | 60° | 90° | 180° |
    |---|---:|---|---:|---:|---:|---:|---:|---:|---:|---:|
    | 原样 | — | 31.391 / 0.1005 | 0 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
    | 全部，余量 15° | 67.6 万 | 31.252 / 0.1019 | 0.553 | 0.211 | 0.015 | 0 | 0.053 | 0.326 | 0.725 | 0.730 |
    | 全部，余量 30° | 67.6 万 | 31.272 / 0.1019 | 0.456 | 0.155 | 0.010 | 0 | 0.023 | 0.210 | 0.593 | 0.730 |
    | 离网格 > 0.3，余量 15° | 45.2 万 | 31.275 / 0.1015 | 0.492 | 0.201 | 0.015 | 0 | 0.053 | 0.278 | 0.545 | 0.234 |
    | 离网格 > 0.3，余量 30° | 45.2 万 | 31.295 / 0.1015 | 0.410 | 0.152 | 0.010 | 0 | 0.023 | 0.197 | 0.459 | 0.233 |

  - 目测（第 104 帧，`E5c_gate/014_compare.png`、`008_compare.png`、`010_compare.png`、`013_compare.png`）：
    - ±90°：离网格 > 0.3 的两个变体去掉了彩色块、白条和左侧的针状碎片，路边地面和灌木保留，上方露出干净的空洞（天空模型的灰色）。
    - 全部屏蔽：连地面、路面也去掉了（180° 曝光 73%），太激进。
    - 最大轴 > 0.3：去掉的不够。
    - −30°：所有变体都与原样几乎相同，没有误删。
    - 60°：余量 15° 比 30° 清得更干净，左侧正常的树和灯杆保留。
- **结论**：判定标准基本达到（FRONT −0.12 dB，略超 0.1 dB 的目标；代价来自离网格且"未观测"的高斯）。E14 采用"离网格 > 0.3、余量 15°、渐隐 15°、最小权重 0.5 像素"。屏蔽成为模型表示的一部分：所有从新视角渲染 E14 的地方都要应用同一个屏蔽。

### E5f：E5c + MTGS 式几何正则（计划）

- **假设**：D-A2 的垃圾是"大尺寸、半透明、靠叠加混色"的高斯。MTGS 的 flatten 正则和惩罚大尺寸，能迫使 FRONT 用贴表面的小面片拟合，侧视更干净，FRONT 代价可接受。
- **改动**：只在 E5c 的配置上加两项上游已有的正则（`models/gaussians/vanilla.py` `compute_reg_loss`）：
  - `model.Background.reg.flatten.w=1.0`（最短轴 L1；MTGS λ_flatten = 1.0，定义不同，未调）；
  - `model.Background.reg.max_s_square_reg.w=0.05`（最大轴平方；上游 OmniRe 对 SMPL 节点用 0.05，未调）。
  - 其余与 E5c 相同，从头训练，种子相同。
- **评测**：FRONT 留出、侧视未观测、D-A2 同一套固定相机与侧视权重分布（大尺寸 / 离网格高斯的占比）。
- **判定**：FRONT 留出下降 ≤ 0.3 dB，且侧视彩色块明显减少（目测），侧视未观测 LPIPS 不变差。
- **输出**：`results/E5f/val056/`。
- **结果**（训练 43.3 分钟；评测 commit `5774b5d`）：

  | 指标 | E5c | E5f |
  |---|---:|---:|
  | 高斯数 | 67.6 万 | 98.4 万 |
  | 最大轴中位数 | 0.091 | 0.022 |
  | FRONT 留出 PSNR / SSIM / LPIPS | 31.39 / 0.910 / 0.101 | 31.36 / 0.913 / 0.092 |
  | FRONT 留出清晰度（渲染 / 真实，拉普拉斯方差） | 0.68 | 0.82 |
  | 侧视未观测 4 相机 PSNR / LPIPS | 16.56 / 0.356 | 16.12 / 0.343 |
  | FRONT_LEFT | 14.07 / 0.280 | 13.59 / 0.272 |
  | FRONT_RIGHT | 16.77 / 0.302 | 16.29 / 0.309 |
  | SIDE_LEFT | 18.06 / 0.460 | 17.37 / 0.437 |
  | SIDE_RIGHT | 17.44 / 0.389 | 17.39 / 0.361 |
  | 侧视权重：来自最大轴 > 1 的高斯 | 32% | 6% |
  | 侧视权重：来自离网格 < 0.1 的高斯 | 11% | 29% |
  | 屏蔽（离网格 > 0.3、余量 15°）后 90° 曝光比例 | 0.55 | 0.14 |

  - 目测（`results/_diagnostics/E5f_common/val056/`，第 104 帧）：±90° 和 60° 的大块彩色糊团没有了，变成大量细小的深色和彩色碎点，背景更多是天空模型的灰色；白条还在；−30° 路边的房子多了碎点；180° 后视的树上有粉色斑点。
  - 判定：三条都满足：FRONT −0.03 dB（≤ 0.3）；彩色糊团明显减少；侧视未观测 LPIPS 没变差（0.343 < 0.356）。另外 PSNR 降了 0.44 dB，是因为侧面露出更多空的灰色，和真实的房子差得更远。
- **结论**：
  - 两项正则把"大糊团"变成了"细碎点"，垃圾变小但没有消失，侧面仍然没有被重建出来。
  - 意外收获：FRONT 留出帧明显更清晰（0.68 → 0.82），LPIPS 也更好，PSNR 基本不变。这是第一个明显缓解"已观测部分也发虚"（OPEN_QUESTIONS 38）、又不损失 PSNR 的改动。
  - E14 仍以 E5c 为起点（已在运行）。如果 E14 的做法有效，下一步可以换成以 E5f 为起点：需要屏蔽的垃圾更少，已观测部分也更清晰。

### E14：视角屏蔽 + 联合深度 + 虚拟经过外观的转向补全

- **假设**：E8–E13 甩不掉侧视垃圾，是因为这些高斯被 FRONT"看到过"，不算空洞，生成不会去替换（D-A2）。用 D-A3 的屏蔽让它们在新视角下消失后，空洞判断能正确地把这些区域交给生成；再配合 MapAnything 联合深度（D-B1）和按轮次分开的外观，补出的内容能进入 3D，而 FRONT 仍由原来的高斯负责。
- **相对 E10 / E13 的改动**（从 E5c 出发）：
  1. **视角屏蔽**：用 E5c 和它的 FRONT 训练视角计算观测锥，只对离 E5c NKSR 网格 > 0.3 的高斯生效，余量 15°、渐隐 15°、最小权重 0.5 像素。所有新视角渲染（目标视角、空洞判断、蒸馏、评测、查看器）都应用；真实 FRONT 视角不应用。新生成的高斯不屏蔽。屏蔽参数与模型一起保存（`view_gate.pt`，并在 config 里登记）。
  2. **蒸馏时不裁剪**：蒸馏阶段不做 densify / cull，这样 E5c 高斯的编号在各轮之间不变，屏蔽参数始终对应得上（E13 用了常规裁剪，这里是一个额外改动）。
  3. **深度**：生成帧用 MapAnything 联合推理（给定内参和位姿，121 帧一次推理），全局尺度；后续轮次复用第 0 轮的尺度。
  4. **监督权重**：验收通过的像素权重 1，无证据的像素 0.3，有冲突的像素 0。在权重 > 0 的空洞像素上生成新高斯。E11–E13 只用通过的像素，通过率太低，3D 基本不变；按 DECISIONS S，未经验证的区域可以"降低监督权重"。
  5. **每轮外观**：每一轮的生成帧当作一次虚拟经过，带一个独立的 3×4 仿射颜色变换（初始为单位变换，加小的 L2 正则），作用在与生成目标比较之前的渲染上；几何和颜色本身与真实 FRONT 共享。这是 MTGS "只共享几何和基色"的简化版（没有做每轮的 SH 残差）。
  6. **轨迹**：沿整段行驶轨迹（隔帧），20 帧内从 FRONT 转到目标偏航，其余保持（与 E10 相同，是带平移的 drive 方式）。4 轮：+45°、−45°、+90°、−90°。
  7. **生成之后重新确定空洞**（冒烟测试后加入，见下）：用 SegFormer 对生成帧做天空分割。新空洞 =（渲染空洞 ∪ 渲染不透明度 < 0.5 的像素）− 生成帧中的天空（`scripts/refine_holes.py`）。
  8. 其余沿用 E13：GEN3C-Cosmos-7B，35 步，seed 1，`consistent` 缓存策略，真实 FRONT 候选 t−0 / 6 / 15 / 30 / 60 / 90（排除留出帧和动态、天空），第 1 轮起用经过验证的生成记忆；验收参数与 E13 相同（平移参考、基线 ≥ 1、视差 ≥ 0.5°、深度 10%、颜色 0.12、≥ 2 票、冲突 ≤ 25%）。
- **评测**：
  - FRONT 留出（19 帧）；
  - 侧视未观测（E5c 定义的像素，4 个相机，SIDE 与 U3 对比），评测渲染同样应用屏蔽；
  - 共同相机（3 位置 × 偏航 −90…180）与 E5c、E10 对比，目测；
  - 每轮的验收通过率、新增高斯数。
- **判定**：
  - 侧视未观测 LPIPS 优于 E10（0.340），且 PSNR 不低于 E8（17.12）；
  - FRONT 留出不低于 E5c − 0.3 dB；
  - 目测 ±90° 不再有彩色块和针状碎片。
