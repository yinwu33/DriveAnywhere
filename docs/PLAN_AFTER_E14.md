# E14 之后的方向（2026-09-28，E14 运行期间）

用户要求："根据现有结果和论文，分析如果当前实验不佳，下一步应该尝试什么方法……牢记目标是从单目 FRONT 重建场景，允许生成想象，可以参考 NVIDIA 最新的 Cosmos 等开源模型。"

目标重述：从单个前视视频得到可自由视角渲染的静态场景。没拍到的部分可以想象，但要满足两点：同一个地方从不同视角看要一致；看起来要像真实街景。能不能和真实的侧相机逐像素对上，不是目标。

实验编号见 [EXPERIMENTS.md](EXPERIMENTS.md)，论文见 [papers/paper.md](papers/paper.md)。

## 1. 已知的事实

| 结论 | 证据 |
|---|---|
| 已观测部分已接近单相机 oracle | E5c 与 U1（FRONT + 真值位姿 + LiDAR）在 FRONT 留出帧和侧视上基本相同（DECISIONS Q） |
| 已观测部分还能更清晰 | E5f 的清晰度比 0.68 → 0.82，PSNR 基本不变（EXPERIMENTS E5f） |
| 侧面在单次经过里几乎没被重建出来 | 去掉离网格的高斯后，90° 侧视几乎全空（D-A2）；U3 的侧视优势来自多相机覆盖（DECISIONS Q） |
| 侧视垃圾是 FRONT 依赖的一层大而离表面的高斯 | D-A2：1.2% 的高斯贡献 80% 的侧视权重；剪掉会损失 FRONT 2–11 dB |
| 按观测锥屏蔽可以把垃圾变成空洞 | D-A3：90° 侧视露出 55% 空洞，FRONT 只降 0.12 dB |
| 逐帧单目深度让生成内容进不了 3D | D-B1：MoGe 逐帧 0.11% 通过，MapAnything 联合 3.6%（E13）/ 20.2%（E12 drive）；E14 第 0 轮 25.4% |
| 生成内容在各视角、各轮之间不一致，蒸馏后被平均掉 | E6 / E7 / E10 的规律；E11 蒸馏后细节相关性只有 0.22–0.26；E10 +60° / +90° 空洞区方差比 0.41 / 0.18（E11_PROBE_RESULTS.md） |
| 缓存覆盖不到的地方，生成器会编内容 | GEN3C 编出远山、阴天、红车（DECISIONS R）；E13 后视在几乎相同的相机处两轮生成的布局不同 |
| 多加角度、轮次、步数不解决问题 | E12 扫视无优势；E13 八个方向两轮，3D 几乎不变 |

E14 第 0 轮（右转 45°）的中间结果：屏蔽后垃圾消失，蒸馏后的 3D 在同一相机和横移 0.5 的新视角里都出现了成片的墙、房子和灌木（`results/E14/val056/r0_after/`）。

## 2. 瓶颈链条

从根本原因到表面现象：

1. **观测缺失**：单次 FRONT 看不到侧面和背面，只能想象（根本限制，除非换成多次经过，见 §5）。
2. **FRONT 专用的"屏幕"**：挡住侧视，又不被当成空洞。E14 用视角屏蔽处理。
3. **生成帧的深度不一致**：E14 改用 MapAnything 联合深度。
4. **想象的内容在各视角之间不一致**：每条轨迹、每一轮各自生成，同一个地方有多个版本，蒸馏时互相抵消、变糊。**这是 E14 之后最可能的主瓶颈。**
5. **生成器的质量和领域差**：在缓存覆盖不到的地方编造内容；GEN3C 最多 2 个缓存；704×1280；没有文本提示（`prompt=""`，`guidance=1`）。
6. **蒸馏丢细节**：目标本身不够清晰；各向同性的新高斯表达能力有限。
7. **评测不适合"允许想象"**：侧视指标是和真实侧相机逐像素比，合理的想象也会被扣分。需要补上一致性、真实感和语义方面的指标。

## 3. 按 E14 的结果选下一步

E14 结束后看四样：侧视未观测区域的指标（对比 E10 的 LPIPS 0.340、E8 的 PSNR 17.12）；共同相机目测（垃圾是否消失、±45° 和 ±90° 两轮补出的同一地点是否一致、清晰度）；各轮的验收通过率；FRONT 留出帧。

| E14 的表现 | 说明瓶颈在 | 下一步 |
|---|---|---|
| 垃圾消失、内容合理但偏糊 | 第 6 条 | E15（从 E5f 出发重跑 E14）；再加 D-D1（渐进更新伪真值 + 逐像素置信度） |
| 垃圾消失，但同一地点在不同轮或视角下是不同版本（重影、两栋房子） | 第 4 条 | **E17（先统一想象的几何，再生成外观）**；辅以 Lyra 2.0 式的历史帧检索 |
| 内容本身不对（远山、凭空出现的车、天空发暗） | 第 5 条 | D-C1（文本提示 + CFG）；E16（Lyra 基线）；E18（按场景做测试时适配） |
| 垃圾仍在 | 屏蔽或空洞判断的实现问题 | 先查实现，不开新方向 |

不论结果如何都先做：D-E1（评测升级）、E15（便宜，而且起点严格更好）。

## 4. 候选方法（按优先级）

### P0：便宜，先做

**E15：以 E5f 为起点重跑 E14**
- **做法**：用 E5f（flatten + 大尺寸惩罚）代替 E5c 作起点。E5f 的已观测部分更清晰；屏蔽后 90° 视角只需露出 14% 的像素（E5c 为 55%），要屏蔽的垃圾少得多。
- **成本**：与 E14 相同，约 4 小时。前提是 E14 的做法本身有效。

**D-E1：评测升级，以"一致 + 真实"为准**（2026-09-29 更正：一致性指标只用于生成帧，最终 3DGS 的渲染天然一致，见 EXPERIMENTS D-E1）
- **做法**：保留现有的逐像素侧视指标，另外增加三类：
  - **多视角一致性**：MEt3R（arXiv 2501.06336，用 DUSt3R 把一个视角 warp 到另一个，再比较特征），以及 2605.18754 提出的基于 COLMAP 的一致性指标。后者指出 MEt3R 这类神经指标会给噪声和重复图像打出高分，基于 COLMAP 的更可靠。
  - **真实感**：侧视渲染和真实 SIDE 相机图像两组之间的 FID / KID。比较的是分布，不要求逐像素一致，只在评测时使用真值。
  - **语义合理性**：SegFormer 在侧视渲染与真实侧相机图像上的类别分布（道路、人行道、建筑、植被、天空）是否接近；以及 ReconDreamer 用的 NTA-IoU / NTL-IoU（车辆和车道线在新视角下是否一致）。
- **成本**：主要是代码，GPU 开销小。所有已有模型都可以重评。

**D-C1：GEN3C 文本提示与 CFG 探针**
- **做法**：GEN3C 现在不用文本（`prompt=""`，`guidance=1`）。用一段固定的场景描述（例如"sunny suburban street, single-story houses, desert landscaping"，可以由 VLM 从 FRONT 帧生成），在 E14 第 0 轮的同一组输入上生成：`guidance` 1 与 3 各一次。
- **比较**：验收通过率、编造内容（目测）、侧视 FID。
- **成本**：每次约 35 分钟（CFG 会让单步计算量翻倍）。

### P1：现成的整套基线

**E16：NVIDIA Lyra（1.0）作为"生成式重建"基线**（Phase 9 修正任务 4）
- **是什么**：Lyra 在 GEN3C / Cosmos 上加了一个 3DGS 解码器，用视频模型自己生成的数据自蒸馏训练，可以从单张图像或单目视频直接输出 3DGS（arXiv 2509.19296，ICLR 2026）。代码 Apache 2.0，权重是 NVIDIA Open Model License。
- **可行性**：官方只在 H100 / A100 上测过，开启完全卸载时峰值约 43 GB，本机 48 GB 可能跑得动。视频输入需要深度、内参和位姿（官方用 ViPE 提取），可以换成我们自己的 MapAnything / GLOMAP 结果；需要核对它的输入格式。
- **意义**：它是 NVIDIA 现成的"单目视频 → 可渲染 3D、允许想象"方案，能告诉我们自建流程和现成方案差多少。
- **成本**：环境搭建和推理，约半天。

### P2：结构性改动，针对"想象的内容不一致"

**E17：先把想象的几何统一成一个 3D，再生成外观**

驾驶场景生成的主流方法走的都是"先几何后外观"：
- LSD-3D：代理几何 + 分数蒸馏；
- InfiniCube（2412.03934）：稀疏体素世界 + 贴像素的引导缓冲 + 前馈提升到 3DGS；
- InfiniVerse（2606.31109）：占据栅格 → 视频 → 再投影回去修正占据栅格；
- SEM-ROVER（2604.06113）：语义体素扩散。

原因都一样：一致性由几何保证，生成器只负责外观。

我们已有的材料：NKSR 网格（已观测部分）、E14 各轮通过验收的生成深度（想象的几何）、E5 的网格初始化和网格深度 / 法向正则。

做法：
1. 把 E14 所有轮次通过验收的生成深度，和已观测部分的融合点云一起重建出一个"想象网格"。点带法向和传感器位置，沿用 Phase 5 和 Phase 7 的流程；来源分别标记为真实或生成。
2. 用想象网格补全 GEN3C 的缓存：每个目标视角的缓存 = 真实帧 warp，缺的地方用想象网格和已有纹理渲染补上，让缓存接近全覆盖。然后再生成一轮外观。
3. 蒸馏时用想象网格做深度和法向正则（E5 的机制）。几何由网格锁定，同一个地方不会再有多个版本。
4. 借鉴 InfiniVerse 的"草图—细化"：新生成的视频再投影回去修正网格，最多迭代 1–2 次。

- **风险**：想象网格本身的质量取决于验收通过率（E14 第 0 轮是 25%，还要看后面几轮）。
- **成本**：以代码为主，重用 NKSR 和 E5 的训练；一次运行约 3–4 小时。

**Lyra 2.0 式的历史帧检索**（可并入 E17）
- 依据：Lyra 2.0（2604.13036）维护每帧的 3D 几何，只用它来检索相关的历史帧、建立稠密对应，外观交给生成模型；训练时加入模型自己生成的历史，抑制漂移。
- 对我们：GEN3C 最多 2 个缓存。当前 `consistent` 策略按覆盖率挑选真实帧和经过验证的记忆。可以改成按可见性分数，从所有真实帧和所有已生成帧里挑。
- Lyra 2.0 本身基于 Wan2.1-14B，在 GB200 上每 80 帧约 194 秒，本机单卡大概率跑不动，所以只借鉴思路。

### P3：需要训练或额外资源（按 DECISIONS S 的准入条件）

**E18：按场景做测试时适配**
- **依据**：CogNVS（2507.12646）用 2D 视频自监督训练补全模型，再在测试视频上微调；World from Motion（NVIDIA，2607.01202）在带模拟伪影的多视角数据上训练"渲染 → 修正"模型，测试时蒸馏回一个一致的 3DGS。
- **做法**：在 val056 的 FRONT 视频上，用 LoRA 微调补全模型：遮住真实帧的一部分，让模型学着补回来。模型可以是本地有的 Wan2.1-VACE-1.3B，或 GEN3C。让模型学到这条街的风格（房子、围墙、植被），减少凭空编造。
- **准入**：需要 E14 和 D-C1 的证据说明现成权重的编造是主要问题，并先在 DECISIONS 里写明基线、目标、数据划分（留出帧不参与）和预算。
- **成本**：1.3B 的 LoRA 在单张 A6000 上可行；GEN3C-7B 需要核实。

**云 GPU 上的更强模型**（需要用户决定，涉及把 Waymo 衍生数据放到云上）
- **Cosmos-Transfer2.5**（2025-10，NVIDIA Open Model License，允许商用）：以深度、分割、边缘、模糊视频为控制条件生成视频。可以用我们渲染的深度和语义作控制，得到符合几何的真实外观。但单卡推理要 65.4 GB 显存，并且需要 Hopper 或更新的架构，本机 A6000 不行。
- **Lyra 2.0**：同上，需要更大的 GPU。
- **Cosmos-Predict2.5**：支持 Ampere，有 2B 和 14B 两个版本。但基础模型没有 3D 缓存或相机控制；驾驶多视角版（`auto/multiview`）要 7 个相机的输入，不适合单个 FRONT。

### P4：蒸馏方式的改进（与 E15 / E17 组合）

**D-D1：伪真值渐进更新 + 逐像素置信度**
- **依据**：DriveX（2412.01717）在优化过程中不断用当前模型的渲染更新伪真值；FaithFusion（2511.21113）用逐像素期望信息增益同时决定"扩散模型改哪里"和"蒸馏时权重多大"；FreeFix（2601.20857）不微调，用图像扩散模型做 2D / 3D 交替细化，并用逐像素置信度只改不确定的区域。
- **对我们**：
  - 把 E14 的手工权重（通过 1 / 无证据 0.3 / 冲突 0）换成基于不确定性的权重；
  - 每一轮结束后，用当前模型重新渲染并低噪声地"修"一遍（我们已有 Fixer 和 SDXL 的基础设施），减轻目标之间的冲突。

**更好的表示**
- 用 2DGS / PGSR 式的面片表示生成区域（E5f 的 flatten 是弱化版）。
- 或者借鉴 Lyra 2.0 用 Depth Anything v3 前馈预测每像素 3DGS 属性，代替现在的各向同性高斯初始化。

### 长期：让侧面内容变"真"

- 多次经过融合：MTGS，Mapillary 计划 §14。这是唯一能让侧面内容真实而不是想象的办法，与生成补全互补。
- NVIDIA Instant NuRec（2607.14203）是前馈的多相机重建，需要标定过的多相机，单个 FRONT 用不了。

## 5. 不建议做的

- 继续增加角度、轮次或训练步数（E12、E13 已说明不解决问题）。
- 只换更大的生成器、不先解决一致性（第 4 条不解决，换什么模型蒸馏后都会被平均掉）。
- 在网格以外的区域做硬剪枝（D-A2：FRONT 会降 2–11 dB）。

## 6. 建议的执行顺序

1. E14 结束后：评测，结果写入登记表。
2. 马上做两件：
   - D-E1：先实现评测，对 E5c / E8 / E10 / E14 统一重评；
   - D-C1：一次 35 分钟左右的生成探针。
3. 按 §3 的分支：
   - 内容合理但糊 → E15 + D-D1；
   - 同一地点多个版本 → E17；
   - 内容本身不对 → E16 + E18（E18 先写准入说明）。
4. 需要云 GPU 的方案（Cosmos-Transfer2.5、Lyra 2.0）只在本地方案都不够时再向用户提。

所有新实验按惯例先在 EXPERIMENTS.md 写方案，结束后写结果。参考的新论文同步加入 papers/paper.md。

## 7. 2026-09-29 夜间结果与修订

用户睡觉期间（2026-09-28 深夜到 09-29 早晨）按 §6 的顺序跑完了 E14，并做了一组诊断。每项的方案和数字都在 [EXPERIMENTS.md](EXPERIMENTS.md)，这里只写结论和对计划的修改。

可视化（Claude Artifact，私有）：https://claude.ai/artifact/2UqDLxF493XkYC67vrn6DG ：侧相机真实感图表与对照表、四个侧相机的同帧对比、D-E2 三个阶段、D-C2 缓存处理、D-C1 提示、第 104 帧环视、E20 进度。图片取自各实验的 `realism2/`、`views/`、`renders/common/` 和 `r0_after/`。

### 7.1 结果

| 实验 | 问的是什么 | 结论 |
|---|---|---|
| E14 | 屏蔽 + 联合深度 + 每轮外观 | 侧视垃圾消失，但被细碎的条纹噪点代替；侧视 LPIPS 0.337（目前最好，但差距很小）；180° 后视退步；90° 两轮验收只有 3% |
| E17a | 统一想象的几何能否去掉噪点 | 几乎没有作用：几何一致性不是噪点的主因 |
| D-A4 / D-A5 | 后视退步从哪来 | 新生成的高斯只在监督过它的方向上可靠；另外 E5c 自己的高斯被侧视监督改动了 → E17b（保护原有高斯） |
| D-B2 | 90° 的冲突是不是深度尺度问题 | 不是。度量标志修好了运动尺度，冲突几乎不变：是生成内容本身在相邻帧之间不一致 |
| D-E1 | 生成补全在"像不像真实街边"上是否有收益 | **没有**。侧面 KID：E5f 0.258、E5c 0.268，所有生成补全 0.31–0.35；生成把一半以上的侧视变成"植被"，建筑从 22% 降到 7% |
| D-C1 | 文本提示能否减少编造 | +45° 内容更像街景（JS 更低），但 KID 不变、验收通过率从 25% 降到 17–18%；不采用 |
| D-C2 | 90° 的"植被"是不是缓存散点诱导的 | 是：缓存仅剩的像素长什么样，GEN3C 就画什么纹理（散点 → 树叶，抹开 → 岩石，去掉 → 编一个完整场景和一辆跟车走的车）。去散点使验收 7.5% → 11%，但没有一种处理画出真实的建筑 |
| D-E2 | 真实感在生成还是蒸馏丢失 | 45°：蒸馏不丢（0.195 → 0.190），但生成本身也没比生成前好；90°：生成带偏类别，蒸馏再丢一大截（0.30 → 0.45）。E14 的 90° 两轮净收益为负 |
| E17b / E17c | 保护原有高斯、最佳视角归属 | 都未达标：保护让被屏蔽的垃圾回来、后视没修好；归属用 1/3 的高斯得到相同指标，噪点还在 |

### 7.2 对瓶颈的新认识

§2 的第 4 条（各视角不一致）仍然成立，但 D-E1 说明更根本的问题在第 5 条：**90° 时生成器本身画出的内容就不对**，大片树篱状纹理代替了路边的房子和空地（`results/E14/val056/views/r2/filled` 与真实 SIDE_RIGHT 对照）。

一个具体的机制（D-C2 正在检验）：
- 90° 时，GEN3C 的缓存里真实帧的 warp 大多是稀疏散点：FRONT 以很斜的角度看到的路边被拉伸到侧视。+90° 时约一半的有效缓存像素是这种散点，+45° 时只有 9%。
- GEN3C 会照着缓存画，零散的彩色点在它看来像树叶。
- E14 侧视的条纹纹理，也可能来自这种斜向拉伸的 warp。

补充（D-C2、D-E2 之后）：90° 时 FRONT 的真实观测只覆盖每帧 2–10%，GEN3C 基本在自由想象，而且想象的内容在帧与帧之间不一致，蒸馏后变成噪点。换缓存处理、换文本提示、换 3D 里的分配方式（E17c）都救不回来。45° 的情况好得多：生成帧与真实前侧相机的分布差距不大，蒸馏也不丢。

### 7.3 修订后的顺序（09-29 早晨更新）

1. **D-E3**（进行中，约 20 分钟）：E14 在第 0 / 1 / 2 轮之后的 checkpoint 按 D-E1 协议评测，估计"只做 ±45°"的侧视真实感。
