# E13：surrounding camera 补全实验

用户于 2026-09-28 要求试一次环视补全。此实验在 val056 局部道路构建八个虚拟方向：前、前左/右、左/右、后左/右、后。所有相机来自 FRONT 自标定相机的估计中心和内参，仅改朝向；不使用真实侧/后相机、GT 或 HUGSIM。

## 执行计划

1. 从 E5c 开始，在 frame 96、104、112 三个位置扫 0→+180°、+180→0°、0→+180°，用平移连接，联合生成右侧和后方。
2. 显式估计统一 MoGe-2→场景尺度，再检查来自不同相机中心的深度/颜色支持。无支持区域保持未知，只有通过区域进入新高斯和生成监督。
3. 更新同一个 3D 场景，保留真实 FRONT 锚定，保存右侧/后方模型快照。
4. 从更新模型渲染另一半 0→−180° 扫视，用实际 warp 的、经过验证的第一轮 RGB-D 记忆作条件。新内容若与验证记忆冲突则拒收；保留第一轮监督共同优化。
5. 输出三位置的八向环视、左右 90°、后侧 135°、正后方 180°、未监督平移，并检查第一轮内容是否被第二轮破坏。

每轮 121 帧、1280×704、冻结 GEN3C 标准 35 步、生成 seed=1；41 个目标、4000 步高斯优化、seed=0。两轮共 242 帧生成和 8000 步场景优化。比此前 +60° 局部诊断扩大了范围，但不宣称解决了旧的几何问题。详细选择与旧代码差异见 [DECISIONS V](DECISIONS.md)。

尺度是估计场景单位；统一尺度给未观测深度提供可检验候选，不给它正确标签。真实缓存仍排除 FRONT 留出源帧、预测动态和天空。高斯初始化较旧实验更密，不启用高斯分裂；这是一次整体方案试验，不是采样方式的单变量消融。

## 运行与记录

```bash
PATH="$PWD/.venvs/main/bin:/usr/local/cuda-12.1/bin:$PATH" CUDA_HOME=/usr/local/cuda-12.1 \
  HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
  .venvs/main/bin/python -u scripts/run_surround_probe.py \
  --config configs/dashrecon/E13_surround.yaml
```

先 commit，再在干净独立 worktree 启动。已有结果目录会显式停止，不覆盖 E5c/E8/E10/E11/E12。结果保存到 `results/E13/val056/surround_20260928/`：配置、meta、源 checkpoint 哈希、两轮 RGB/深度/几何验收/缓存来源、采样记录、模型快照、共同相机、报告和逐阶段日志。

首轮代码 `37a774f` 在生成阶段主动中止：frame 104 正后方的静态真实缓存覆盖为零；仅最近 15 帧不足以覆盖回看区域。原输入和原因保留在 `surround_20260928/ABORTED.json`，不是完成质量结果。

正式重跑显式扩大真实 FRONT 历史候选为 t−0/6/15/30/60/90；仍排除留出源帧和动态/天空。每轮增加不加载生成网络的缓存预检，再做相同的 35 步生成。新输出为 `results/E13/val056/surround_20260928_history/`，相同两轮和优化预算。实现与 19 项合成/采样测试通过；没有把环视质量、后方几何、五场景或可测试仿真资产标为通过。
